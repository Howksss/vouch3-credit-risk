# vouch3-credit-risk

**English summary.** Credit-risk part of Vouch3, a monitoring service for Russian corporate
bonds and digital financial assets. Two things live here. First, a rule-based decision
strategy for grading instruments: versioned rule sets (`rules_v1` → `rules_v2`), an additive
penalty scheme and a factor log on every decision. These are pure functions with no database,
and the tests run with plain `pytest`. Second, an out-of-time backtest that checks whether
free public data (MOEX ISS, the Federal Tax Service financial statements registry, the 1prime
disclosure feed, company-register status) can rank issuers by default risk *before* the event.
Point-in-time features, a 250-day label window, train through 31.12.2024, test on 31.12.2025.
Financials plus disclosure behaviour reach AUC 0.755 against 0.634 for a size-only baseline.
With shuffled labels the same pipeline never exceeds 0.579 in 20 runs. A paired bootstrap puts the gain over size alone
at +0.122 (90% CI +0.038…+0.213). The shipped dataset contains features and labels keyed by an
HMAC of the issuer's tax ID under a discarded random key: no company names and no per-company risk scores.

## Задача

Ранжировать эмитентов облигаций по риску дефолта, используя только бесплатные открытые
данные и только то, что было известно **до** события. Проверка — out-of-time бэктест.

## Данные

Все источники бесплатные, без авторизации и ключей. Снимок данных — 08.09.2026.

| источник | что берём | объём |
|---|---|---|
| MOEX ISS `/iss/securities` | универс эмитентов | 10 553 выпуска → 1 540 ИНН, включая погашенные |
| ПРАЙМ, `disclosure.1prime.ru` | события (метки) и поведение в раскрытии | 138 851 сообщение, страницу отдали 1 437 из 1 540 ИНН, архив с декабря 2022 |
| ГИР БО, `bo.nalog.gov.ru` | отчётность: баланс, ОПиУ, ДДС | 766 эмитентов, периоды с 2020 года |
| MOEX ISS `/iss/history` | цена, доходность, дюрация на дату среза | все котировки на каждую дату среза |
| ЕГРЮЛ (статус в карточке ГИР БО) | ликвидация как событие | 46 эмитентов в стадии ликвидации |

Эмитентов с сообщением о неисполнении обязательств — 71. Год первого дефолта:
2022 — 3, 2023 — 11, 2024 — 12, 2025 — 21, 2026 — 24.

## Дизайн бэктеста

- **Срезы `as_of`:** 30.06 и 31.12 за 2023–2025.
- **Признаки только из отчётности, опубликованной до среза.** Дата доступности — дата
  публикации (`actualBfoDate` / `datePresent`), а не конец периода. Отчётность за 2024 год
  появляется в апреле–мае 2025 и до этого в модель не попадает. Признаки раскрытия
  считаются по сообщениям с датой не позже среза.
- **Метка:** стресс-событие в окне `(as_of, as_of + 250 дней]`. Горизонт одинаковый у всех
  срезов, иначе фолды несравнимы. Событие в сам день среза будущим не считается.
- **Обучение** на срезах до 31.12.2024, **тест** на 31.12.2025. Срез 30.06.2025 выброшен:
  его окно меток пересекается с тестовым, один и тот же будущий дефолт был бы меткой
  и в обучении, и в тесте.
- **Модель:** L2-регуляризованная логистическая регрессия (IRLS на numpy). Медианы,
  клиппинг по 2/98 перцентилям и стандартизация считаются только на обучении.

**Правила универса** влияют на результат сильнее модели:

1. Эмитент должен быть **виден на ПРАЙМе** на дату среза, то есть публиковал что-то за
   последние 12 месяцев. Иначе его дефолт не наблюдаем и он попал бы в фальшивые «хорошие».
2. Выброшены банки, СФО и ипотечные агенты: балансовые коэффициенты у них значат другое.
3. Выброшены те, кто **уже в дефолте** на дату среза: ранжировать их — не прогноз.

Итог: 1 428 наблюдений, 319 эмитентов. Обучение — 913 наблюдений и 55 событий,
тест — 264 наблюдения и 31 событие (база 11.7%).

**Широкая метка:** неисполнение обязательств, право требовать досрочного погашения,
банкротство, приостановка эмиссии, реструктуризация, ликвидация в ЕГРЮЛ.
**Жёсткая (`--hard`):** только «неисполнение обязательств эмитента перед владельцами
ценных бумаг».

Правила против утечки закреплены тестами: отчётность до публикации не видна, границы
окна метки, разбиение без пересечения окон, фильтр универса.

## Результаты

Out-of-time, тест 31.12.2025, 264 эмитента. ДИ — 90%, бутстрап по эмитентам.

| модель | AUC, широкая метка (31 событие) | 90% ДИ | топ-20% списка ловит | AUC, жёсткая (20 дефолтов) |
|---|---|---|---|---|
| только размер (null model) | 0.634 | [0.545, 0.712] | 9 из 31 | 0.672 |
| только отчётность | 0.728 | [0.654, 0.788] | 13 из 31 | 0.732 |
| отчётность + раскрытие | **0.755** | [0.683, 0.815] | 15 из 31 | 0.730 |
| только рынок | 0.564 | [0.471, 0.649] | 7 из 31 | 0.770 |
| всё вместе | **0.784** | [0.719, 0.835] | 16 из 31 | **0.794** |
| макс. доходность облигаций, один признак без модели | 0.768 | — | — | **0.832** |

Топ-20% списка модели «отчётность + раскрытие» ловит 15 событий из 31 при точности 29%
против базы 11.7%.

**Прирост к модели «только размер»** (парный бутстрап по эмитентам, те же выборки для обеих моделей):

| | широкая метка | жёсткая метка |
|---|---|---|
| только отчётность | +0.094 [+0.018, +0.169] | +0.061 [−0.027, +0.144] |
| отчётность + раскрытие | +0.122 [+0.038, +0.213] | +0.058 [−0.046, +0.154] |
| всё вместе | +0.150 [+0.066, +0.240] | +0.122 [+0.015, +0.228] |

На широкой метке прирост устойчив. На 20 жёстких дефолтах фундаментальная модель от
размера статистически не отличима, отличим только вариант с рынком.

**Пермутационный тест** (`permutation_test.py`). Метки перемешиваются внутри обучения и
теста с сохранением числа событий, весь пайплайн прогоняется заново 20 раз:

```
real labels        AUC = 0.755
shuffled labels    mean = 0.490  sd = 0.054  max = 0.579
real above shuffled in 20/20 draws
```

Реальный результат на 4.9 sd выше нуля. Разбиение, признаки и фильтр универса скрытой
информации о метке не несут.

**WOE-скоркарта против логита** (`scorecard.py`). Карта на 13 блоках с границами бинов,
заданными кредитной логикой, а не подобранными по данным. Веса бинов сжаты к базовой
ставке. Out-of-time AUC 0.670 против 0.755 у логита (жёсткая метка: 0.593 против 0.730).
Логит на шести признаках (пять коэффициентов и наличие рейтинга) даёт 0.616. При 55 событиях в обучении
регуляризованная регрессия на полном наборе выигрывает у фиксированной карты.

Одиночные признаки на тесте (широкая метка): максимальная доходность 0.768, минимальная
цена 0.687, капитал/активы 0.620, ROA 0.581, ICR 0.530, долг/активы 0.510. Классические
коэффициенты поодиночке почти бесполезны, работает их комбинация с размером и
поведением в раскрытии.

**Панель: больше строк не значит больше информации** (`panel.py`, `panel_sweep.py`).
Переход с 6 полугодовых срезов на 36 месячных, l2 = 5:

| окно метки | шаг сетки | строк обучения | строк с событием | эмитентов с событием | AUC |
|---|---|---|---|---|---|
| 250 дн | 1 мес | 6 046 | 375 | 53 | 0.751 |
| 250 дн | 3 мес | 1 983 | 121 | 47 | 0.750 |
| 250 дн | 6 мес | 1 097 | 64 | 46 | 0.752 |
| 180 дн | 1 мес | 6 046 | 277 | 46 | 0.738 |
| 90 дн | 1 мес | 6 046 | 153 | 40 | 0.694 |
| 31 дн | 1 мес | 6 046 | 57 | 33 | 0.616 |

6 046 строк дают то же, что 1 097: за ними стоят одни и те же ~50 эмитентов с событиями.
Дискретная hazard-модель с месячным окном — AUC 0.632, 90% ДИ [0.536, 0.710]. По той же
причине не помогло бы синтетическое раздувание (SMOTE): новых дефолтнувших эмитентов
оно не добавляет.

## Что не доказано

- **Интервалы широкие.** 31 событие в тесте по широкой метке и 20 по жёсткой. AUC 0.755
  — это [0.683, 0.815]. На жёсткой метке фундаментальная модель не отличима от размера.
- **Одна тестовая дата.** Out-of-time точка одна (31.12.2025). Скользящей проверки по
  нескольким тестовым срезам нет.
- **Перенос на ЦФА не проверен.** Модель обучена на эмитентах облигаций. У ЦФА нет
  вторичного рынка, а значит, нет и самого сильного признака — доходности. Открытой
  истории дефолтов ЦФА нет, проверить перенос сегодня не на чем.
- **Покрытие источников.** ПРАЙМ — один из нескольких центров раскрытия: эмитенты,
  публикующиеся только в других центрах, в универс не попадают. Отчётность в ГИР БО
  нашлась у 766 из 1 540 эмитентов, банки и госструктуры она не покрывает.
- **Метка шумная.** Сообщение о неисполнении включает и технические просрочки на пару дней.

## Модуль стратегии

`strategy/grade.py` — правила присвоения грейда инструменту (облигации или ЦФА).
Чистые функции над dataclass'ами: `Instrument`, `Issuer` на входе, `Grade` на выходе.
Шкала — 12 ступеней от `A+` до `D-`, индекс ступени — сумма штрафов, обрезанная до 0…11.

**Версии.** Каждый `Grade` несёт `model_version`. В продукте грейды лежат в таблице
`grade (instrument_id, model_version, score, grade_label, factors jsonb, computed_at)`
с уникальным ключом `(instrument_id, model_version)`. Версии сосуществуют, и любой
выставленный грейд можно восстановить по правилам своей версии.

- **`rules_v1`** — сектор плюс три флага условий бумаги. Сектор задан явно или угадан по
  ключевым словам в названии. Купон выше 25% — +1, номинал от 1 млн — −1, срок короче
  90 дней — +1. Дробная часть суммы отбрасывается. В лог пишутся только входы.
- **`rules_v2`** — два блока штрафов, у каждого правила свой вес. Сумма округляется до
  ступени, в лог пишутся входы, сработавшие правила и вклад каждого.

| блок | правило | штраф |
|---|---|---|
| условия | купон > 30% / > 25% | +2.0 / +1.0 |
| | номинал ≥ 1 млн (институциональный выпуск) | −0.5 |
| | срок < 90 дней / > 3 лет | +0.5 / −0.5 |
| эмитент | сектор: банк / промышленность / ритейл / прочее / девелопер | 0 / 1.0 / 1.5 / 2.0 / 2.5 |
| | идентификация: ОГРН / только ИНН / только название | −0.5 / −0.25 / +0.5 |
| | дефолтные выпуски в истории | +3.0 |
| | отменённые выпуски | +0.5 за каждый, не больше +1.5 |
| | погашено ≥ 3 / ≥ 1 / первый выпуск | −1.0 / −0.5 / +0.5 |
| | эмитент не опознан | +3.0, блок эмитента не считается |

**Стоп-факторы.** Жёсткого отказа, то есть грейда `D-` без скоринга, в `rules_v2` нет.
Роль стоп-факторов играют нокаут-штрафы: дефолт в истории (+3 ступени) и неопознанный
эмитент (+3, остальные проверки эмитента пропускаются). Они сдвигают грейд, но не
обнуляют его.

**Лог факторов.** Выпуск со ставкой 32% у эмитента с известным ИНН, первый выпуск:

```json
{
  "terms":   {"coupon_rate": 32.0, "coupon_flag": "very_high", "term_days": 365},
  "credit":  {"sector": "Other", "identity": "inn_verified", "total_issues": 1,
              "active_issues": 1, "redeemed_issues": 0, "track_record": "first_issue",
              "issuer_avg_coupon": 32.0},
  "penalties": {"coupon>30": 2.0, "sector=Other": 2.0, "inn_verified": -0.25, "first_issue": 0.5},
  "raw_score": 4.25
}
```

Грейд `B` (ступень 4). `penalties` в сумме всегда равны `raw_score`, это проверяется тестом.
Тот же выпуск по `rules_v1` получает `B+`.

**История эмитента** — один агрегирующий запрос [`strategy/issuer_stats.sql`](strategy/issuer_stats.sql).
Алиасы колонок совпадают с ключами, которые читает `rules_v2`. Запрос идёт и на
PostgreSQL, и на SQLite ≥ 3.30, поэтому тест гоняет его на in-memory SQLite без внешней БД:

```python
# SQLAlchemy
row = conn.execute(text(ISSUER_STATS_SQL), {"issuer_id": 42}).mappings().one()
grade = compute_grade_v2(instrument, issuer_stats(row))
```

**Ограничения `rules_v2`**, видные из бэктеста:

- Веса экспертные, не откалиброваны на событиях. На каталоге продукта 91% выпусков
  получили грейд группы A: шкала почти не различает.
- Сектор угадывается по названию эмитента.
- «Погашен» в данных означает «дата погашения прошла», а не «эмитент заплатил». Статус
  `defaulted` из внешнего источника не проставляется, так что дефолтный штраф на практике
  не срабатывает.
- Доходность — самый сильный одиночный предиктор в бэктесте (0.832 на жёстких дефолтах),
  а в `rules_v2` она лишь штраф +1/+2, который перекрывается бонусами за ОГРН и историю
  погашений. Следующая версия правил должна строиться от доходности и отчётности, а не от
  метаданных.

## Как воспроизвести

Python 3.10+, зависимости — numpy, pandas, pytest.

```bash
pip install -r requirements.txt
pytest                          # 27 тестов, без БД и сети

cd backtest
python model.py                 # бэктест, широкая метка
python model.py --hard          # только дефолты
python permutation_test.py      # контроль утечки
python scorecard.py             # WOE-карта
```

Без собранных данных скрипты читают опубликованный датасет
[`backtest/dataset/semiannual.csv.gz`](backtest/dataset): 2 402 строки (эмитент × срез)
до фильтра универса — признаки, обе метки и флаги универса. ИНН заменён на HMAC со
случайным ключом, который не сохранён. Названий, ОКВЭД, региона и сумм из отчётности нет,
модельных оценок по компаниям в репозитории нет. На этом датасете все цифры выше
воспроизводятся точно, включая бутстрап.

Полный пайплайн из источников (сырые выгрузки в репозиторий не входят, их собирают харвестеры):

```bash
cd backtest
python iss_universe.py          # универс MOEX -> data/moex_issuers.json
python bfo_harvest.py           # отчётность ГИР БО, резюмируемо, ~40 мин
python prime_harvest.py         # раскрытие ПРАЙМ по каждому ИНН, резюмируемо, ~2 ч
python iss_prices.py            # рынок на даты срезов, ~2 мин
python build_labels.py          # события из сообщений
python add_egrul_events.py      # + ликвидации из ЕГРЮЛ
python build_features.py        # point-in-time признаки из отчётности
python build_disc_features.py   # признаки раскрытия и наблюдаемость
python model.py
python export_dataset.py        # пересобрать опубликованный датасет
```

Месячная панель: `build_features.py`, `build_disc_features.py` и `iss_prices.py` с флагом
`--monthly`, затем `panel.py` и `panel_sweep.py`. Источники живые: новые сообщения и
перезалитая отчётность сдвинут цифры относительно снимка 08.09.2026.
